# adam-operator-crds

> Moved into adam-rs from `vymalo/another-agentic-platform` at commit [`cfd03db`](https://github.com/vymalo/another-agentic-platform/tree/cfd03db836b39fd4ff81ac0275f2602781ab19c4) ([ADR 0029](../../docs/decisions/0029-adam-rs-has-an-operator.md)). `§N`, `AD-NNN`, `Sn` and `M0`..`M3` in this file cite that repository's design documents (`docs/architecture`, `docs/mvp.md`) as of that commit, which is archived; they are not links into this one.

The CustomResourceDefinitions of the operator, `agentservices.agents.vymalo.com` and `agentconfigs.agents.vymalo.com`
(`v1alpha1`), as a chart of their own. A separate chart because the CRDs are installed by their own Argo CD Application in the
infrastructure project, and upgraded apart from the operator.

```sh
helm template adam-operator-crds deploy/operator-crds | kubectl apply --server-side -f -
```

Server-side apply, as Argo CD's `ServerSideApply=true` sync option does: the CRDs are 55 KB, and a client-side apply keeps a copy
of the manifest in an annotation.

## One source

The CRDs are generated by `cargo run -q -p adam-operator -- crdgen > deploy/crds/agents.vymalo.com.yaml`
([`bin/adam-operator`](../../bin/adam-operator/README.md)). A Helm chart reads only its own directory, so this chart holds a **copy**,
[`files/agents.vymalo.com.yaml`](files/agents.vymalo.com.yaml), read with `.Files.Get` (never as a template: nothing in it is
expanded). Two checks hold the three places equal: `sh deploy/operator/tests/render-check.sh` (the copy equals
`deploy/crds/agents.vymalo.com.yaml`, and what the chart renders is that file) and the `crds` job of
[`operator.yml`](../../.github/workflows/operator.yml) (it also runs `crdgen`). After a change to a type in `adam-operator-api`:

```sh
cargo run -q -p adam-operator -- crdgen > deploy/crds/agents.vymalo.com.yaml
cp deploy/crds/agents.vymalo.com.yaml deploy/operator-crds/files/agents.vymalo.com.yaml
```

## Removing it

Deleting the release deletes the CRDs, and with them every `AgentService` and `AgentConfig` (the operator's finalizers then no
longer run, so the agents' objects are left to their owner references). Nothing here keeps them (`helm.sh/resource-policy`):
protect them in the Argo CD Application (`Prune=false`, as home-os does for objects that hold data), not in the chart.
