# A session's config may lower its access tier, never raise it (ADR 0054 slice 8)

Card: ANR-218. Base: `21b7e6ec`.

## What it does

`SessionConfig::access_tier` is a ceiling on the access tier of every round of a child session
(`access-tier/v1`, ADR 0036). It is admitted against the tier of the run that starts the session — the
parent's, or the person's message — and the deployment's `MAX_ACCESS_TIER`, and it may only lower
them:

* a `plan` session of an `auto` parent is **offered no write tool** (`TierSource::withhold`), and a
  **named** write tool is **refused at the tool** (`Gated`), not merely hidden;
* a tier above the parent's is refused where the other options are, with
  `config.access_tier is bypass; at most auto, the tier of the session's parent`;
* a deployment that lists no access tiers **refuses the option** rather than ignore it
  (`this deployment lists no access tiers`).

## Where the ceiling rides, and why that seam

`SessionConfig` lives in the run's state (the session header), but `SourceCtx` and `ToolCtx` are built
from the round's inbound context, so the ceiling rides the context **beside** the tier and the mode:
`vymalo.session.accessTier` = `{"ceiling": "plan"}` (or `{}` when the session set none), written from
the header's clamped config by `round_message` (`subagent_start`/`subagent_send`) and by the A2A
front's `put_header`, exactly as slice 3's `vymalo.session.tools` is. The key is one of
`PROTECTED_CONTEXT_KEYS` (unlike the tools key): a child run of a session must stay under the ceiling,
and a ceiling a large context could drop would lift the limit. The header's config stays the truth, and
an edit refreshes the key in the state it commits, so a mid-round edit applies at the next model call.

The **starter's grant is added at the call**: `SessionBounds::for_starter(context)` (or `narrowed_to`
for the A2A front, whose person's tier comes from the message's metadata) narrows the deployment's
tier set to the lower of the named tier and any parent ceiling, else the deployment's default, and
`admit` refuses a tier that set does not honour. A later round clamps the same way, so a message that
lowers the tier lowers the session with it.

`AccessTier`/`AccessTiers` moved to `adam-model` (beside `ReasoningEffort`, the same argument) and
`adam-a2a` re-exports them at the same paths: one closed list for the protocol, the runtime and the
loop, since `adam-runtime` cannot depend on the protocol crate.
