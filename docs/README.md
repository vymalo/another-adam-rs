| [Decisions](decisions/) | Architecture decision records. [0001](decisions/0001-library-first-host-roles.md): adam-rs is library-first; hosts run a control plane and workers through the closed `Role` enum and supervisor in `adam-host`. [0002](decisions/0002-workspace-placement.md): the closed `Placement` enum (`shared`, `affinity`, `isolated`, `a2a-only`), pinned claims over a run owner, and a cross-process mirror lock. [0003](decisions/0003-a-new-task-continues-the-task-it-references.md): a new A2A task that references a finished one (`referenceTaskIds`, same caller, same context) starts from its conversation, through `init_continuing`, with the carried history capped. [0004](decisions/0004-agent-folders-at-run-time.md): a binary reads its agent folder (`ADAM_AGENT_DIR`) once, at startup, and the coder falls back to the copy embedded in its binary; no hot reload in release images, a restart is a deploy. [0005](decisions/0005-one-binary-serves-any-agent-folder.md): `adam-agent` is one binary that serves any agent folder (no embedded default, one agent per process, `ask_user` and the folder's MCP tools only), over `adam-service`, shipped inside the coder image. [0006](decisions/0006-a2ui-and-the-vymalo-extensions-in-adam-rs.md): a question can carry an A2UI interface, a message's extensions are the run's inbound context (the screen's UI catalog, the thread-tools grant kept until it expires), tools can come from a `ToolSource` read at every model turn, and `adam-ui` turns the screen's catalog into `ask_user` with Choices, `show` and `ui_catalog`. [0007](decisions/0007-progress-as-steps-and-streamed-text.md): a request's activated extensions reach the backend, a tool call and the work it drives are `Step` events (the orchestration layer's `steps/v1`, a line of text for a client that did not activate it), and the model's answer is streamed as it is written (issue #51: the `text-stream/v1` extension, `RunEvent::TextDelta`, the streamed model step in the journal, only the final text stored). [0008](decisions/0008-a-workspace-holds-several-repositories.md): a run's workspace is a directory of slots, each a repository's worktree or a scratch project (a local repository with an empty root commit, kept only until the run ends and copied into a repository all or nothing), a repository has one slot per run, the workspace is deleted with the run, an empty remote gets an empty first commit, and which repository may enter is the coder's rule: the person named it, or agreed when the coder's `request_repository` asked or the coder created it after the person agreed (`create_repository`; both built). [0009](decisions/0009-github-per-installation-read-through-mcp.md): the coder is authenticated per installation, by a token or a GitHub App (`GitHubApp` signs a JWT with the App's key, parsed at startup, and trades it for an installation token it keeps until five minutes before it expires, behind `HostScoped`; every token it mints is redacted), its own tools stay in process, GitHub is read through the official GitHub MCP server (read-only, built: the coder image carries a pinned `github-mcp-server`, the shipped `mcp.json` lists twelve read tools, and its flags, variables and behaviour are verified against v1.12.2) and a repository is created only for an allow-listed owner, empty and private by default, after the person agrees every time (built: `create_repository`, with `CodeHost::create_repository`, `owner_kind` and `authenticated_login`). [0010](decisions/0010-a-run-works-in-its-repositorys-devcontainer.md): a run's commands run in its first repository's `devcontainer.json` (a default image when it has none) on a rootless Podman service, through the official devcontainer CLI and the new crate `adam-devcontainer` (an `Environment` of `adam-workspace`); the file is untrusted and checked three times, nothing of the coder's environment enters the container, nothing is silent, and the run's container and images are removed with it (built: the crate and the dev stack, and the coder composes it: `DEVCONTAINER_RUNTIME=podman`, `rebuild_environment`, OpenCode in the container; off by default, and off on Kubernetes). [0011](decisions/0011-a-tool-calls-step-carries-its-input-and-output.md): a tool call's step carries what the tool was given (`input`, on the report that starts it) and what it answered (`output`, on the one that ends it), cut to 4 KiB and 8 KiB (head and tail), redacted by the agent first (the coder's `Redactor`, `adam-agent`'s environment values) and by the orchestration layer after, with a switch (`StepIo::off()`); a step too big for a `NOTIFY` crosses without them; an MCP tool's `title` is the label of its step; amends 0007 decision 3. [0012](decisions/0012-files-as-a2a-artifacts.md): a file an agent made is an A2A artifact whose one part is `raw`, with `mediaType` and `filename` and no extension (`Artifact::file`, `#[non_exhaustive]` and serde-additive, so earlier journals still decode; the bytes are base64 in the journal, capped at 4 MiB a file and 6 MiB a run, the loop refusing what would go over); the model is told one line and never the bytes; the coder's `share_file { path, repo?, name? }` reads one file of the workspace under `read_file`'s confinement, types it by extension with the bytes checked for images (a disagreement or an unknown extension is `application/octet-stream`), and its text is scrubbed by the redactor (built: all of it, over A2A, tested on memory and PostgreSQL). [0013](decisions/0013-run-keeps-changes-edit-file-and-scratch-completion.md): the coder's shell has three tools of one job each (`run_command` looks and its changes are undone, `run` makes and its file changes are kept but nothing of git, `run_checks` checks and is the only one the gate sees; `run` is never a check, and a command that touches git is undone entirely), `edit_file { path, old, new, replace_all? }` replaces exact text and, when it cannot, shows the closest region of the file, and scratch work that shared a result (a file, with no repository named, created, pushed or continued) completes without a pull request, the owner's decision 2 of 2026-10-02; scratch projects get five check cycles (`SCRATCH_CHECK_CYCLES`) and repositories keep three (built: all of it). [0014](decisions/0014-a-turn-output-answer-is-the-runs-answer.md): a tool can announce the run's answer (`ToolOutput::announcing`, kept in `Conversation::announced`, journaled with the call's result, the last announcement wins, an error announces nothing, a message that reaches the run clears it), and the run's output `text`, so the A2A `completed` status message, is that answer and not the model's closing line (which is still said, as working text, and names no stream); `adam-ui` uses it for the orchestration layer's thread tool `turn_output { text }` and tells the model *Delivered to the person as your answer. Finish now with one short line*, and the instructions say "if you have a `turn_output` tool" (built: all of it). [0015](decisions/0015-tools-the-orchestrator-reports-long-calls-and-mentioned-agents.md): a thread tool says how long it may take (`_meta["thread-tools/v1"].timeoutSecs`) and whether the orchestrator reports its step (`reportsStep`), the agent waits that long capped by `THREAD_TOOLS_MAX_CALL_SECS` (3600) and reports no step of its own for a reported tool, what a listing says travels with the model's answer (`ToolNote`, `Conversation::source_notes`), a call carries `_meta {callId, parentStepId}` with a `callId` of `<run id>:<call id>` that a retried step repeats, the mentions of the latest message are the run's context (`vymalo.mentions`, cleared by a message with none) and a source can add a "Mentioned agents" block to the instructions only when there are some, and the card lists `mentions/v1` (built: all of it). [0016](decisions/0016-a-message-sent-to-a-working-task-is-steered-into-it.md): with `steer/v1` activated, a message that names a `submitted` or `working` task is delivered to its run's inbox (durable) and read at its next step; a final answer written while a message is unread takes another model turn (`Ctx::arrived`, `Ctx::reopen_on_arrival` closes the window to the commit, a recorded answer that predates a read message is dropped); a message is read once per `messageId` (`Conversation::read_ids`); a message to a finished task is `UnsupportedOperationError`; without the activation it is refused as before; the card lists `steer/v1` (built: all of it). [0017](decisions/0017-a-github-app-works-on-every-account-it-is-installed-on.md): a GitHub App is not tied to one installation: without `GITHUB_APP_INSTALLATION_ID` the installation is found from the owner of the repository (`GET /orgs/{owner}/installation`, then `GET /users/{owner}/installation`, with the App's JWT), only for the owners a required allow-list names (a public App can be installed by anyone, so the installation proves nothing), with one lookup at a time per account (a 60 second memory of "not installed", dropped and looked up once more when a mint answers 404), one mint at a time per installation, at most 64 installations and 256 accounts kept, and typed errors that name the App (built: `GitHubApp::discovering` and `AppOwners` in `adam-workspace`, the coder's `GITHUB_APP_OWNERS`, GitHub read through `github-mcp-server http` as a sidecar with the token of each call (`CallBearer` in `adam-mcp`, `GitHubReadBearer` in the coder), the redactor's bound; planned: read-only tokens for the MCP calls). [0018](decisions/0018-extra-mcp-servers-are-a-file-merged-over-the-agents-own.md): extra MCP servers are a file (`ADAM_EXTRA_MCP_FILE`, the shape of `mcp.json`) added to the agent's own at startup, never replacing one (a name clash is exit 78), a server may be `optional` (skipped with a warning when down, unkeyed or lacking an allow-listed tool, instead of exit 69), a header whose variable is empty is an error, and every `${VAR}` a `mcp.json` names is hidden from the processes of runs (`HidingEnvironment`) and redacted (built: all of it). |

## Writing docs

* A process gets a Mermaid pair: a `sequenceDiagram` for the interaction and a
  `stateDiagram-v2` for the lifecycle. Prose says what the diagrams cannot.
* Every node, edge, state and call in a diagram must exist in the code. Cite
  the file, for example `crates/adam-runtime/src/runtime.rs`.
* Mark third-party claims *verified* (with date and source) or *unverified*.
* Do not copy a crate README. Link to it.
* `node tools/docs-check/check-docs.mjs` parses every diagram and resolves every
  relative link and `#heading`, and checks the first-party skills. CI runs it in
  the `docs` job. Install once with `npm --prefix tools/docs-check ci`.
