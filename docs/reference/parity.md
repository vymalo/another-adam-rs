# Parity of adam's surfaces

The owner's rule (2026-11-21): *"Adam-coder / adam-agent / ... All should have the same settings / features (maybe not in
the same way, ones usng a2a extensions, another via api, another via direct crates - e.g when embedded,...)"*.

This page is the matrix of every user-facing setting and feature by surface, each cell checked against the code, and the
list of what is missing. **A new setting or feature updates this page** in the same pull request: [How to keep
parity](#how-to-keep-parity).

## Surfaces and pins

| Column | What it is | Where its settings live |
|---|---|---|
| **coder** | `adam-coder` | environment variables ([Environment](environment.md)), the chart `deploy/coder` ([its README](../../deploy/coder/README.md)), the card's A2A extensions, its embedded files `bin/adam-coder/agent/` |
| **agent** | `adam-agent`, a folder agent | the folder ([Agent files](agent-files.md)), the same shared variables, the card |
| **engine** | `adam-engine`, adam embedded in an application ([ADR 0047](../decisions/0047-adam-rs-can-be-embedded-in-an-application.md)) | the crate: `Engine::builder`, `Limits`, the model client and the store the host gives ([its README](../../crates/adam-engine/README.md)) |
| **system** | the orchestrator and the web of vymalo/another-agentic-system | what it reads from the live card, its per-message API (AG-UI `forwardedProps`) and REST API, the web |
| **platform** | vymalo/another-agentic-platform | the `AgentConfig`, `AgentService`, `ModelEndpoint` and `ToolProvider` CRDs, the dashboard's forms, the Platform API, `aapctl` |

Citations are `repo:path:line`: `adam:` is this repository at `99f64b2`, `sys:` another-agentic-system at `ebcee350`, `plat:`
another-agentic-platform at `dd8bba3`, all read on 2026-11-21. The engine's profile and level cells were added in
[#317](https://github.com/vymalo/another-adam-rs/pull/317), after the `99f64b2` pin; the pin is not moved.

## Legend

| Tag | Mechanism |
|---|---|
| `env` | a variable read once at startup; a bad value is exit 78 |
| `chart` | a value of `deploy/coder`; `extraEnv` there is `config.extraEnv` (`adam:deploy/coder/values.yaml:119`), a variable the chart has no key for |
| `files` | the agent folder: frontmatter of `instructions.md`, `mcp.json`, `commands/`, `schedules/`, `subagents/` |
| `card` | an A2A extension the card lists, activated by the client for each message |
| `crate` | the Rust API: the engine's builder and calls, or the `adam-model-openai` client the host builds |
| `api` | the orchestrator's API: AG-UI `forwardedProps` of a run, or REST (`sys:docs/api/chat-api.yaml`) |
| `ui` | the web |
| `crd` | a field of the platform's CRDs |
| `form` | a field of a dashboard form: what the Platform API takes, and so what `aapctl apply` writes (`plat:bin/cli/src/forms.rs:1`) |
| `yaml` | a CRD field no form says: the object is shown as YAML only, and the Platform API and `aapctl apply` refuse it (`plat:crates/forms/src/represent.rs:37`); `kubectl` still applies it |
| `crd extraEnv` | `AgentConfig.spec.extraEnv` (`plat:crates/api/src/config.rs:69`): literal variables the operator does not set itself, `yaml` |
| **same** | the same mechanism as the column to the left |
| **gap** | missing: listed under [Gaps](#gaps) |
| **planned** | decided or proposed, not built |
| **n/a** | does not apply, for the reason given |

## How to keep parity

* **A new setting or feature fills every column** in the pull request that adds it: the variable and the chart value,
  the folder key, the engine's builder or `Limits`, the card. A column of another repository gets its cell from the
  contract this repository publishes (the card, `deploy/coder`, which the platform renders its goldens from).
* **A column it cannot fill opens an issue** in the repository that should fill it, and the pull request links the issue
  from the cell's line under [Gaps](#gaps). A cell is never empty: a mechanism with its `repo:path:line`, **gap**, or
  **n/a** with the reason.
* **A changed citation moves with the code**: when a cited line moves, update it; when a pin is moved, read the other
  repositories again at their new commits and update [the pins](#surfaces-and-pins).
