# adam-code-tools

The file and command tools of an adam-rs agent, as a library
([ADR 0047](../../docs/decisions/0047-adam-rs-can-be-embedded-in-an-application.md), decision 7). They move here
from [`adam-coder`](../../bin/adam-coder/README.md) in steps, behind a `CodeWorkspace` port that the coder
implements over its worktrees and a host can implement over a person's own directory (slice 7).

## Where it sits

Below the coder and above [`adam-workspace`](../adam-workspace/README.md), which it uses **without** its `github`
feature: the GitHub code host and the App's credentials stay the coder's. It depends on `adam-llm-agent` and
`adam-runtime`, not on the `adam` facade, so it does not bring `adam-assembly` and its HTTP client. Unix only for
now: the commands run through a login shell and kill a process group (Windows is slice 8).

It holds what the tools are built on and, so far, the tools that read: `list_files`, `find_files` and
`search_files` (`find`), then `read_file` and `read_files` (`files`), and three that write, `write_file`, `edit_file`
and `apply_patch` (`files`). The commands have their port, `CommandWorkspace` with the guard of a command, and the
plumbing `run_command` and `run` share (`commands`, `output`); `run_command` (`inspect`) and `run` (`make`) are here. The
background commands (`start_command`, `stop_command`, `list_commands`), `run_checks` and the worktree's `Snapshot` and its
restores are still the coder's. `adam_coder::tools::{shell, sandbox, access}`, `adam_coder::redact` and
`adam_coder::tools::gitcli` re-export these modules, and the coder's `tools::output` and `ToolEnv::run` delegate to them, so the coder's API and its tests are unchanged.

## API at a glance

| Module | What |
|---|---|
| `commands` | **The commands' port**, `CommandWorkspace` (`DynCommandWorkspace`), which **extends** `CodeWorkspace` (a command finds its place with the same `place()`): `session(ctx)` → `Arc<dyn EnvSession>`, where a command runs (the implementation reports the session to the call's usage, `Meter::report_session`); `limits()` → `CommandLimits` (`timeout`: the limit of a command that asks for none and the most one may ask for; `output_tail`: the bytes a result shows); `kept()` → `&dyn KeptOutputs`, where a long output is kept for `read_output`. **The guard of a command**: `guard(ctx, place, Guarding)` → `Box<dyn CommandGuard>`, **required**, taken before the command (`Err` is the refusal the model is told, and nothing runs); `CommandGuard::settle(self: Box<Self>)` → `Settled` after it (`Unchanged`, `FilesChanged`, `Undone { restored }`, `Unreadable { restored }`, `Unwatched`; `#[non_exhaustive]`), and a guard dropped without settling undoes nothing; `Guarding` (`Look`: nothing may change; `Make`: files may, git may not); `Unwatched`, the guard of a workspace that watches and undoes nothing (a person's directory). `after_run(ctx, place)` → text, **required**: after a command that makes things ran and before its guard is settled (the coder moves its check epoch; the text, empty or starting with `'\n'`, is appended when files changed; `run_command` never calls it). Provided: `refusal_note(ctx, place)` (empty by default), appended to the guard's refusals and to a command it undid, and `missing_tool_answer(ctx, place, &MissingTool, dirs, &dyn EnvSession)` → `Option<String>` (`None` by default: the command's own result). `run(ws, ctx, session, spec, timeout, tail_cap, keep)`: `shell::run_captured` (`keep`) or `run_timed` in `session`, stopped by the run's cancel, the tail of an output that is not kept scrubbed with the bytes before it, and in a metered sandbox the time it ran reported (ADR 0043). `environment_error(redactor, &EnvError)` and `run_error(redactor, &RunError)`: a command that did not run as a `ToolError` (transient or permanent by the error's class, scrubbed, a failed build's log tail included); `cancelled(what)`, the error of a tool whose run was cancelled. The coder's `session_error` (which sends the model to `rebuild_environment`) stays the coder's |
| `inspect` | **`run_command`** as a function of a `&dyn CommandWorkspace` and a `ToolCtx`, declared by the coder's `tools::inspect` as `find`'s tools are. In order: the command required, `timeout_of` the limits, `place(Read)`, `resolve_cwd` against `place.path()`, the session, `guard(Look)` (its refusal and the `refusal_note` is the answer, nothing runs), the progress line `running: <command>` (scrubbed), `commands::run` and `output::settle`, `settle()`: a command undone or unreadable is refused (`undid a change made by: <command>`, the text names `run` and the file tools, with the note); a missing tool is the workspace's `missing_tool_answer` when it has one (`the workspace lacks a tool`); else the result (`$ <command>`, how it ended, `output::section`) with its repeat key, and, when the guard kept files it saw change (`FilesChanged`), a line that says they stay (`changed files: <command>`). `render(command, &ShellOutcome)`, the result's text, which `run` uses too. It never calls `after_run` |
| `make` | **`run`** as a function of a `&dyn CommandWorkspace` and a `ToolCtx`, declared by the coder's `tools::make`. In order: the command required, `timeout_of` the limits, `place(Write)`, `resolve_cwd`, the session, `guard(Make)` (its refusal and the `refusal_note` is the answer, nothing runs), `running: <command>`, `commands::run` and `output::settle`, then **`after_run` before `settle()`** (so the coder's check epoch moves for a command its guard then undoes too); `settle()`: `Unreadable` is refused (`could not check git after: <command>; undid it`), `Undone` is refused (`undid a change to git made by: <command>`), each with the note and naming `commit_and_push`; a missing tool is the workspace's answer when it has one; else `render`'s result and, for `FilesChanged`, the files `git status` lists (at most `MAX_LISTED`, 20, then how many more) and the text of `after_run` (`changed files: <command>`), for `Unchanged` a line that git sees no change, for `Unwatched` nothing more (`ran: <command>`), with its repeat key. **Known, kept as they are:** a failing `after_run` is the tool's error and the guard is dropped unsettled, so a change to git stays; the first entry listed loses its leading space (`status_text` is trimmed); a file put back as `HEAD` is said as an ignored file |
| `output` | What the model is shown of a command's output: `settle(ws, ctx, &mut ShellOutcome)` scrubs it with `ws.redactor()` and, when it is longer than `limits().output_tail` once scrubbed, shows its head (a quarter) and tail cut at line ends and keeps it whole in `ws.kept()` under the call's output id (a capture that is only the start of the output is cut back where no secret straddles); `section(&ShellOutcome)`, the output section of a result (`--- output ---`, or the head, `[... N bytes not shown ...]`, the tail and the `[more: ...]` line, every other line that starts with `[` written `\x5b`, `escaped`); `head_of`, `tail_of`; `timeout_of(&CommandLimits, asked)`: the limit when none is asked, an error for less than 1 s or more than the limit (never clamped). Moved whole from the coder's `tools::output` |
| `shell` | Running a command for a tool: `run_in`, `run_timed`, `run_captured` (cwd confined to the worktree, a timeout that kills the whole process group, output capped to its tail), `shell_spec`, `resolve_cwd`, `cwd_key`, `spawn_prepared`, `kill_group`, `login_shell`; `ShellOutcome` (`passed()`, `repeat_key()`), `KeptNote`, `RunError`; a command the shell cannot find is `missing_tool` → `MissingTool`, with `project_dependency_hint`; `KEPT_OUTPUT_MAX`, `SCRUB_OVERLAP` |
| `sandbox` | `Meter`: the time a run's commands run in a metered sandbox (a run pod), reported as usage on the call's `ToolCtx` ([ADR 0043](../../docs/decisions/0043-sandbox-time-as-usage.md)); `Meter::of(session)` is `None` where nothing is metered |
| `access` | The scopes the tools share with the other calls of a model turn ([ADR 0049](../../docs/decisions/0049-the-tool-calls-of-a-turn-run-at-the-same-time.md)): `FILES`, `COMMANDS`, `LSP`, and the access functions of the tools with two uses (`runs_a_command`, `makes_files_with_a_command`, `stops_a_command`, `lists_the_commands`, `asks_a_language_server`) |
| `confine` | Where a tool may read or write: `confine(root, path, Access)` → `Confined` (`rel()`; it cannot be built outside the crate), or the reason the model is told. An empty path, a NUL byte, an absolute path, `..`, any `.git` component (any case) and the root itself are refused; a read follows only the links that stay inside the place; a write refuses any link on the way. The file tools open with `open_for_read(root, path)` and `locate_for_write(root, path, create)` → `Located` (read-only accessors), which **check the path themselves** as `confine` does, against the root as it was opened (`SlotDir`), never its name; `parts_of` and `is_dot_git` are the rule's parts |
| `find` | **The first tools over the port**: `list_files`, `find_files` and `search_files` as functions of a `&dyn CodeWorkspace` and a `ToolCtx` (one place by `place(Read)`, its nested instructions before the page, its redactor over every line before it is matched). Their declarations (name, description, the model's arguments) are the caller's: the coder's `tools::find` declares them and delegates here. Bounded by what is done, sorted by bytes, a timeout an error and never a partial page (`within`, `DEADLINE` 30 s); `search_files_in` behind `test-util` |
| `files` | **All five file tools over the port, the read tools and three write tools**: `read_file` (one page of a text file in the paging convention, at most 2000 lines and 50 KiB, `offset`/`limit` or the old `start_line`/`end_line`; an image offered to a model that sees the workspace's images; a missing file names the closest paths `git` lists) and `read_files` (the first page, 400 lines or 8 KiB, of 1 to 16 files in one result of at most 32 KiB, each file that cannot be shown one line; room for a block of nested instructions, `MAX_INSTRUCTIONS_BLOCK`, kept so that a claimed block is always shown), as functions of a `&dyn CodeWorkspace` and a `ToolCtx`, declared by the coder's `tools::files` as `find`'s are; `READ_FILES_MAX`, `READ_FILES_LINES`, `READ_FILES_PAGE_BYTES`, `READ_FILES_TOTAL_BYTES`. **And three write tools**: `write_file` (a file created or replaced with exactly its content, at most `WRITE_CAP`, 1 MiB: parents made, a new file renamed over the target, the mode kept) and `edit_file` (exact text replaced once or, with `replace_all`, everywhere; line endings and trailing blanks tolerated when the exact text misses, leading whitespace never; a miss shows the closest region with its line numbers and the first difference, two places are refused with their lines) and `apply_patch` (a unified diff of at most `PATCH_CAP`, 1 MiB, applied all or nothing by `git apply` through the place's `git`: every path git reads from the patch confined for writing first, a symlink or submodule mode and a binary patch refused, a second reading with `--recount` when git cannot read or apply it as written; a place whose repository is refused applies nothing), each on `place(Write)` and followed, when the write succeeded, by `CodeWorkspace::after_write`, whose text ends the tool's sentence; `Written` and `Edited` (what a write and an edit did). `read_in`, `write_in` and `edit_in` (the work without a workspace, for race tests) behind `test-util`. **A file's text is not scrubbed here**: the coder scrubs every result in its `Redacting` layer, and a host that serves these tools scrubs their results with its own redactor before the model sees them |
| `git` | Where the tools ask `git`: `GitAt` (`slot(&Slot)`, `worktree(&Worktree)`; pinned to the slot's repository as the workspace's metadata names it, and **refused** when it cannot tell, so no `git` is started), `git_stdout`, `status_text` (`git status --porcelain=v1 -z --untracked-files=all`, trimmed as `git_stdout` trims: moved from the coder's `tools::gitcli`, which re-exports it), and the one question every file tool asks, `list_files` (tracked and untracked files, without what git ignores, sorted by bytes, at most `MAX_LISTED_PATHS` paths and `MAX_LISTED_BYTES` of answer) → `ListError` (`Unavailable`, `TooMany`, `Failed` with no path of this machine in it); `list_files_within` with other limits. The coder's git writes and restores stay in `adam-coder` and ask at the same `GitAt` |
| `workspace` | **The port**, `CodeWorkspace` (`DynCodeWorkspace`): `place(ctx, repo, Intent)` → `Place`: the place `repo` names, or with none **the only place that may be written** (a read-only place is used when named, never by default); for `Intent::Write` never a read-only one. `Err` is the tool's answer, an error result for the model or a `ToolError` (`Outcome`). `redactor()`. `nested_instructions(ctx, place, path, Target)`, provided (`None` by default): a block returned is **claimed** (counted as shown, so the tool shows it) and at most `MAX_INSTRUCTIONS_BLOCK` (12 KiB). `after_write(ctx, place, paths)`, **required**: called after a write tool changed `paths` (relative to `place`), it returns text the tool appends verbatim to its sentence, empty or starting with `' '` or `'\n'` (the coder moves its run's check epoch, says to run the checks again and, in a published scratch project, that the change does not reach the repository; `DirWorkspace` returns nothing); an `Err` is the tool's, the files stay written. `Place::new(name, GitAt)` takes its root from the `GitAt`, so the directory a path is checked against is the one `git` writes in; `read_only()`, `with_handle(T)` and `handle::<T>()` (exactly a `T`, for the implementation's own methods), `name()`, `root()`, `path()`, `git()`, `is_writable()`. `Intent` (`Read`, `Write`), `Target` (`File`, `Dir`, `Either`). The coder implements it over the slots of a run (`ToolEnv`); the conformance cases are [`adam-code-tools-testkit`](../adam-code-tools-testkit/README.md). The commands' trait, `CommandWorkspace`, extends this one (`commands`). **To come:** with a host's implementation (slice 7), a `GitAt` for a directory no workspace metadata describes |
| `redact` | `Redactor`: the process's secrets replaced by `[redacted]` (`REDACTED`) in everything that leaves it, with their Base64 forms; `new`, `add` (a secret learned later, the latest `MAX_ADDED` kept), `add_fixed`, `add_env_values`, `scrub`, `scrub_string`, `scrub_value`, `failure_text` (`MAX_FAILURE_TEXT`), `step_io`, and what a stream that scrubs in pieces needs (`longest`, `margin`, `partial_secret_len`); a clone shares its secrets, so one added later is scrubbed by every clone. Values shorter than `MIN_SECRET_LEN` are not registered. `Redactor::from_config` (the secrets of the coder's configuration) and `RedactingCredentials` stay in `adam-coder` |

## Breaking changes

* `CodeWorkspace::after_write` is a **new required method** of the trait: every implementation must add it (the coder's
  `ToolEnv` and the testkit's `DirWorkspace`, this repository's only ones, have it). One that has nothing to do after a
  write returns `Ok(String::new())`.

* `CommandWorkspace::guard` and `CommandWorkspace::after_run` are **new required methods** (step 5c-1): every
  implementation of `CommandWorkspace` must add them (the coder's `ToolEnv` and the testkit's `DirWorkspace`, this
  repository's only ones, have them). One that watches nothing returns `Ok(Box::new(Unwatched))` and `Ok(String::new())`.
  `refusal_note` and `missing_tool_answer` are provided.

**Not a break:** `CommandWorkspace` itself (step 5b) was additive: an implementation of `CodeWorkspace` alone is
unchanged; only a workspace that serves commands implements it.

## Tests

Next to the code: `shell.rs` (the cwd confinement, the timeout that kills the group, the output cap, the
missing-tool recognition, a run in a session of the caller's own), `find.rs` (the three tools' pages, limits, order, escapes and what a search cannot tell of a secret: the coder's tests, moved), `files.rs` (a read's pages, its one pass over a file, the old range names, a long line cut, a binary file or a directory not read, a read out of time, the closest paths, and paging that reassembles the file, a property test; a write that creates its parents, replaces, keeps the mode and leaves nothing behind, the 1 MiB limit, no write through a link, a file a read holds left whole; an edit once or everywhere, its tolerance of line endings and trailing blanks and the exact spans it replaces, the closest region of a miss, two places refused, what it cannot edit; the paths `git apply --numstat -z` names, a symlink or submodule mode in its summary, the files of a patch listed with a limit, and a patch applied by the git of the sandbox (`apply_sandbox_tests`, which needs `adam-workspace`'s `test-util` as a dev-dependency): the coder's tests, moved), `confine.rs` (the rule on both uses: an empty path, `..`, an absolute path, `.git` in any case and not `.github`, a link to a file or a directory outside, an absolute link, one that goes up past the root and one that comes back, a link to `.git`, a write through any link, a root that is a link or a file, a directory written as a file; `locate_for_write` checking the path itself; the coder's tests, moved. The races, a slot or a directory swapped while a tool works, are the coder's `swap_tests`, which swap its slots), `output.rs` (a long output's head and tail cut at line ends, its view with the id, a line the command printed that cannot forge the kept line, an output that could not be kept, a short one shown whole: the coder's tests, moved; `settle` and `commands::run` over a workspace are the testkit's `command_cases`), `inspect.rs` (a result says how the command ended without calling it a failure; the refusal of a changed worktree says what happened and where changes go: the coder's tests, moved; `run_command` over a scripted workspace, each verdict's text and progress line, is the testkit's `tests/run_command.rs`, and its answers in the coder's worktrees are pinned by the coder's `tests/command_results.rs`), `make.rs` (the changes listed from `git status` with a rename counted once, many cut and counted, none said as ignored files; a refusal of a command that touched git says everything was undone and where commits go; one after which git could not be read does not say it changed git: the coder's tests, moved; `run` over a scripted workspace is the testkit's `tests/run.rs`), `git.rs` (the listing: tracked and untracked merged and sorted by bytes, a `.git` of any case left out, a name that is not UTF-8, too many paths or bytes stops `git`, no path of this machine in what `git` said) and `redact.rs` (every position of a split secret,
the Base64 forms, clones that share what is added later, the one-pass scrub against the sequential one, a megabyte
against 650 needles). `cargo test -p adam-code-tools` (needs `git`); nothing needs a database.
